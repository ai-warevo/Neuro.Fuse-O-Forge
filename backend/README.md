# ⚙️ Neuro.Fuse-O-Forge: Backend Core
Эта директория содержит всю серверную логику системы, разделенную на два ключевых компонента: управляющий узел (API) и вычислительные узлы (Workers).

## 🏗 Архитектура бэкенда
Бэкенд спроектирован как распределенная система, где связь между компонентами осуществляется через Redis.

   1. API (/api): Асинхронный сервер на FastAPI. Служит прослойкой между пользователем и очередью.
   2. Workers (/worker): Универсальные исполнители на PyTorch. Каждый экземпляр воркера изолирован и работает со своей нейросетью.
   3. Config (config.yml): Единый конфигурационный файл, определяющий лимиты, пути к моделям и правила очистки данных.

## 🔄 Схема взаимодействия

   1. API получает запрос -> Валидирует его -> Кладет задачу в Redis Stream (forge:tasks:{type}).
   2. Worker (соответствующего типа) забирает задачу -> Генерирует контент -> Пишет логи в Redis Pub/Sub (logs:{task_id}).
   3. API слушает Pub/Sub канал и транслирует данные пользователю через WebSocket.
   4. Worker сохраняет результат в папку /output и отправляет ACK в Redis.

## 🛠 Установка зависимостей (для разработки)
Если вы запускаете бэкенд без Docker (локально), установите зависимости:

### Для API
pip install -r api/requirements.txt

### Для Воркеров (требуется CUDA)
pip install -r worker/requirements.txt

## 🔐 Безопасность и Ресурсы
* VRAM: Каждый воркер держит модель в памяти. Используйте параметр auto_unload_timeout в конфиге, если ресурсов GPU недостаточно для постоянного хранения всех моделей.
* Очистка: Бэкенд автоматически удаляет временные файлы из /output. Настройте retention_hours в глобальном конфиге.

## 📡 Переменные окружения
Каждый компонент ожидает следующие ENV:
* REDIS_HOST: адрес брокера (по умолчанию localhost).
* FORGE_TYPE: (только для воркеров) — IMAGE, SOUND, TEXT или UI.
