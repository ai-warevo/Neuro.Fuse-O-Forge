# 🎨 Фронтенд — Neuro.Fuse-O-Forge (Next.js App)
Фронтенд представляет собой SPA-интерфейс на базе Next.js, обеспечивающий визуальный контроль над процессом генерации. Главная особенность — работа в реальном времени через WebSockets и глубокая интеграция с мониторингом GPU.

## Технологический стек
* Framework: Next.js 14+ (App Router, SSR).
* State Management: Zustand (управление логами, историей и статусом GPU).
* Стилизация: Tailwind CSS + next-themes (Dark/Light режимы).
* Локализация: next-i18next (Поддержка RUS / ENG).
* Уведомления: Web Push API (для фоновых уведомлений о готовности задач).

## Архитектура и Роутинг
Приложение разделено на тематические «цеха» (Forge Units):
* / — Dashboard: Живая статистика всей системы и воркеров.
* /image — Visual Forge: Интерфейс генерации изображений.
* /sound — Sonic Forge: Интерфейс генерации аудио.
* /text — Lexi Forge: Работа с текстом и LLM.
* /ui — Layout Forge: Генерация интерфейсов.

## Компоненты интерфейса (UI)
### Header (Глобальный контроль)
* GPU Monitor: Виджет нагрузки (Load %, VRAM MB, Temp), обновляемый каждые 5 сек.
* Language Switcher: Переключение RUS / ENG.
* Theme Switcher: Переключатель тем (по умолчанию — киберпанк-темная).

### Forge Studio (Рабочая область)
* Settings Panel (Слева):
* Поле ввода с кнопкой ✨ AI Enhance (автоматическое улучшение промпта перед отправкой).
   * Динамические параметры (слайдеры steps, guidance, duration и т.д.).
* Forge Terminal (Справа):
* Окно консоли для вывода логов из WebSocket в реальном времени.
   * Предиктивный и реальный Progress Bar.
* Gallery (Снизу):
* Горизонтальная лента истории задач.
   * При клике на результат — модальное окно с деталями и кнопкой «Скачать».

## Взаимодействие с Backend
   1. Создание задачи: POST /api/generate -> получение task_id.
   2. Связь: Открытие WebSocket ws://.../ws/task/{task_id}.
   3. Обработка событий:
   * type: log -> добавление строки в терминал.
      * type: progress -> обновление шкалы прогресса.
      * type: success -> пуш объекта в Zustand historyStore, вывод результата, Push-уведомление.
      * type: error -> отображение ошибки в консоли.
   
##  Логика истории (Persistence)

* При инициализации приложение делает запрос GET /api/history для наполнения галереи.
* Все новые задачи сохраняются в локальном стейте и синхронизируются с базой данных на бэкенде.

## Инструкция для разработки:

   1. Установить зависимости: npm install.
   2. Настроить переменные окружения в .env.local (указать адрес API).
   3. Запустить сервер разработки: npm run dev.
